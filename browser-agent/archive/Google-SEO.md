## 2. AI 功能和您的网站

**URL:** https://developers.google.com/search/docs/appearance/ai-features?hl=zh-cn

**核心描述:**
从网站所有者角度介绍 AI 概览和 AI 模式等 AI 功能在 Google 搜索中的运作方式，以及如何让内容纳入这些体验。

**关键要点:**
- AI 概览：针对复杂查询，帮助用户更快掌握要点，提供多样化网站链接
- AI 模式：针对需要探索、推理或比较的查询，一次提问获得全面的 AI 生成回复
- 两者都可能使用"查询扇出"技术，在子主题和数据源中发出多项相关搜索
- AI 概览只在系统认为可以为经典搜索提供补充时才显示

**技术要求:**
- 网页必须已编入索引、符合摘要显示条件、遵循搜索技术要求
- 无其他特定技术要求

**SEO 最佳实践:**
- 确保 robots.txt 和 CDN/托管架构允许抓取
- 通过网站内部链接让内容更容易被发现
- 为用户提供出色的网页体验
- 确保重要内容以文字形式提供
- 使用优质图片和视频辅助文字内容
- 确保结构化数据与可见文本一致
- 检查 Merchant Center 和商家资料信息
- 在 Search Console 中验证网站

**效果衡量:**
- AI 功能中的网站流量计入 Search Console 总体搜索流量
- 在"网页"搜索类型的效果报告中统计
- 可在 Search Console 分析总体流量变化，结合 Google Analytics 使用

**控制显示:**
- 可通过预览控件进行问题排查

## 3. 署名日期

**URL:** https://developers.google.com/search/docs/appearance/publication-dates?hl=zh-cn

**核心描述:**
指导网站如何正确显示署名日期（发表日期和更新日期），以及 Google 如何在搜索结果中使用这些信息。

**关键要点:**

### 署名日期指引
- Google 搜索结果可能会在标题链接下方显示日期信息
- 日期信息可帮助用户判断内容的新旧程度和相关性

### 最佳实践
- 在网页上清晰显示发布日期和最后更新日期
- 日期应醒目易见，通常位于标题附近
- 使用标准日期格式，确保机器可读
- 更新文章时应更新日期，但不要为了显得新鲜而虚假更新
- 避免对没有实质更新的内容更改日期

### 结构化数据
- 可以使用结构化数据标记日期信息
- 使用 schema.org/Article 中的 datePublished 和 dateModified 属性

### 需避免的做法
- 不显示日期或隐藏日期
- 虚假更新日期而不做实质性修改
- 对旧内容仅更新日期而不更新内容本身

## 4. 网站图标（Favicon in Search）

**URL:** https://developers.google.com/search/docs/appearance/favicon-in-search?hl=zh-cn

**核心描述:**
指导网站如何使用网站图标（favicon）在 Google 搜索结果中显示，提升品牌识别度。

**关键要点:**
- Google 搜索结果中会在网站名称左侧显示网站图标
- 网站图标有助于用户识别和记忆品牌

### 技术要求
- 网站图标必须是有效的图片格式（SVG、PNG、ICO 等）
- 图标尺寸建议为 48x48 像素或更大
- 图标应与网站主题相关，清晰地代表品牌
- 必须在网站首页或通过 `<link>` 标签引用
- 图标 URL 必须可公开访问

### 最佳实践
- 使用高对比度、简洁的设计
- 确保图标在浅色和深色背景下都可见
- 定期更新以保持品牌一致性

### 需避免的做法
- 使用透明度过低的图标
- 使用过于复杂、在小尺寸下难以辨认的设计
- 使用与品牌无关的通用图标

## 5. 精选摘要（Featured Snippets）

**URL:** https://developers.google.com/search/docs/appearance/featured-snippets?hl=zh-cn

**核心描述:**
精选摘要是 Google 搜索结果顶部显示的特殊内容区块，直接从网页中提取内容以快速回答用户问题。

**关键要点:**
- 精选摘要自动从网页内容中提取，无需手动标记
- 通常出现在搜索结果的顶部位置（位置 0）
- 包含段落、列表、表格等形式

### 类型
- 段落摘要：从文章中提取的一段文字
- 列表摘要：有序或无序列表形式
- 表格摘要：以表格形式呈现数据

### 如何优化
- 清晰、直接地回答常见问题
- 使用明确的问题/答案格式
- 提供结构化的内容（标题、列表、表格）
- 确保内容准确、可靠

### 效果
- 精选摘要可以显著提高点击率
- 即使位于页面顶部，也可能影响网站流量
- 可通过 Search Console 监控

### 需避免的做法
- 不要为了抢占精选摘要而提供低质量内容
- 不要重复已有的精选摘要内容
- 不要使用误导性信息

## 6. 灵活抽样（Flexible Sampling）

**URL:** https://developers.google.com/search/docs/appearance/flexible-sampling?hl=zh-cn

**核心描述:**
灵活抽样是 Google 搜索中对网站内容进行抽样索引的策略，允许 Google 根据内容质量和类型灵活决定索引范围。

**关键要点:**
- Google 可能会对网站进行"抽样"而非完整索引
- 抽样的程度取决于网站的内容质量、结构和技术健康状况
- 高质量、原创内容更可能被完整索引
- 低质量或重复内容可能导致更大幅度的抽样

### 影响因素
- 内容质量和原创性
- 网站结构和导航
- 技术 SEO 健康状况
- 内部链接架构

### 最佳实践
- 确保所有重要页面都是高质量的原创内容
- 使用清晰的网站结构和导航
- 优化内部链接以帮助 Google 发现和评估内容
- 使用站点地图提交所有重要页面
- 避免重复内容问题

### 效果
- 索引范围直接影响搜索流量
- 被抽样的页面可能不会出现在搜索结果中

## 7. Google 探索（Google Discover）

**URL:** https://developers.google.com/search/docs/appearance/google-discover?hl=zh-cn

**核心描述:**
Google 探索是 Google 提供的内容推荐功能，用户无需搜索即可在移动设备上获得个性化内容推荐。

**关键要点:**
- Google 探索是 Google 应用和移动端 Chrome 中的内容流
- 基于用户的兴趣、搜索历史和浏览行为进行个性化推荐
- 内容源不限于搜索索引

### 内容要求
- 内容必须符合 Google 探索的内容政策
- 推荐高质量、时效性强的原创内容
- 内容应包含大尺寸图片（至少 1200px 宽）
- 使用引人注目的标题和描述

### 优化建议
- 使用大尺寸、高清图片（推荐 1200px 以上）
- 创建令人信服且准确的标题
- 关注时效性内容
- 建立受众信任
- 避免误导性标题

### 效果衡量
- Google 探索流量在 Search Console 中独立报告
- 可监控展示次数、点击次数

### 需避免的做法
- 点击诱饵（clickbait）标题
- 令人震惊或误导性内容
- 低质量或拼凑内容

## 8. 图像（Google Images）

**URL:** https://developers.google.com/search/docs/appearance/google-images?hl=zh-cn

**核心描述:**
指导网站如何在 Google 图片搜索中获得更好的展示效果，提高图片的可见性和流量。

**关键要点:**
- Google 图片搜索是重要的流量来源
- 图片不仅可以来自网页内容，也可以独立被发现

### 技术优化
- 使用描述性文件名（而非 IMG001.jpg）
- 使用 alt 属性描述图片内容
- 确保图片可被抓取（robots.txt 不阻止）
- 使用支持的图片格式（JPEG, PNG, WebP, SVG 等）
- 优化图片加载速度
- 为图片提供上下文相关的周围文本

### 结构化数据
- 可使用 ImageObject 结构化数据标记图片元数据
- 包括图片的创作者、许可信息等

### 最佳实践
- 使用高质量、原创图片
- 在图片周围提供相关文字描述
- 使用响应式图片
- 为产品图片使用多个角度

### 需避免的做法
- 使用文字内容密集的图片
- 使用低质量或模糊图片
- 使用盗用或未授权图片

## 10. 网站名称（Site Names）

**URL:** https://developers.google.com/search/docs/appearance/site-names?hl=zh-cn

**核心描述:**
指导网站如何在 Google 搜索结果中显示正确的网站名称，提升品牌识别和用户信任。

**关键要点:**
- Google 搜索结果中会在标题链接上方或旁边显示网站名称
- 网站名称通常自动从网站内容中提取

### 如何设置网站名称
- 使用结构化数据（WebSite 类型）指定网站名称
- 网站名称应清晰、准确地代表品牌或网站
- 在网站首页标题和内容中一致使用同样的名称

### 技术实现
```json
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "网站名称",
  "url": "https://www.example.com"
}
```

### 最佳实践
- 使用品牌名称作为网站名称
- 保持一致性（全站统一）
- 网站名称应简短、易识别

### 需避免的做法
- 在名称中添加关键词堆砌
- 使用与品牌无关的描述性短语
- 频繁更改网站名称

## 11. 站内链接（Sitelinks）

**URL:** https://developers.google.com/search/docs/appearance/sitelinks?hl=zh-cn

**核心描述:**
站内链接是 Google 搜索结果中在网站首页下方显示的额外链接，帮助用户快速导航到网站的重要部分。

**关键要点:**
- 站内链接是 Google 自动生成的，无法手动配置
- 通常出现在品牌搜索或网站名称搜索中
- 链接到网站的主要导航部分

### 影响站内链接的因素
- 网站结构和导航清晰度
- 内部链接架构
- 页面之间的关联性
- 用户对特定页面的访问频率

### 优化建议
- 创建清晰的网站导航结构
- 使用描述性的锚文本
- 确保重要页面在导航中突出
- 使用面包屑导航提供路径信息
- 保持网站结构的稳定性和可预测性

### 需避免的做法
- 不要尝试操纵站内链接
- 不要添加大量不相关的页面到导航中

## 12. 片段（Snippet）

**URL:** https://developers.google.com/search/docs/appearance/snippet?hl=zh-cn

**核心描述:**
摘要（Snippet）是搜索结果中在标题链接下方显示的网页内容摘要，帮助用户了解页面内容。

**关键要点:**
- 摘要通常从页面内容中自动提取
- 摘要可以包含文字、结构化数据信息
- Google 可能会选择与用户查询最相关的内容作为摘要

### 如何影响摘要
- 创建高质量、清晰的内容
- 使用描述性的元描述（meta description）
- 在页面开头提供内容的概要
- 使用清晰的标题结构

### 元描述最佳实践
- 每个页面应有独特的元描述
- 准确概括页面内容
- 包含相关关键词和用户意图
- 长度建议 150-160 字符
- 加入明确的行动号召

### 需避免的做法
- 使用空元描述或默认描述
- 元描述与页面内容不匹配
- 在所有页面使用相同元描述
- 在元描述中堆砌关键词

## 13. 标题链接（Title Link）

**URL:** https://developers.google.com/search/docs/appearance/title-link?hl=zh-cn

**核心描述:**
标题链接是 Google 搜索结果页上链接到对应网页的搜索结果的标题。Google 会综合多种信息自动确定标题链接，但网站可以通过最佳实践指明偏好。

**关键要点:**
- 标题链接是用户决定点击哪个结果时参考的主要信息
- Google 完全自动生成标题链接，同时考量网页内容及网络对此网页的引用

### 最佳实践
- 每个网页的 `<title>` 元素指定独特、简练的描述性标题
- 避免关键字堆砌，不要重复相同字词
- 避免重复或样板化文字，每个网页应有独特描述
- 简明扼要地在标题中宣传品牌，建议在标题开头或末尾加网站名并用分隔符隔开
- 明确指出哪些文字是网页的主要标题（放在 h1 中，使用更大字体）
- 使用与网页主要内容相同的语言和书写系统

### 常见问题及 Google 应对
- `<title>` 元素不完整：Google 可能改用其他文字
- `<title>` 已过时：Google 可能选择其他来源
- `<title>` 不准确：Google 可能替换为更准确的描述
- 微样板文字（样板标题）：如"乐队名称 - 查看视频、歌词、海报、专辑、评价和音乐会"，Google 可能忽略
- 主要标题不明确：确保主要标题有别于其他文字
- 书写系统/语言不一致：Google 会尝试显示与网页主要语言相符的标题
- 网站名称重复：仅在首页或不重复的情况下包含
- 避免在 `<title>` 中添加航班价格信息（价格频繁变化，可能导致不一致）

### 关于 robots.txt 和 noindex
- robots.txt 阻止抓取不阻止编入索引
- 使用 noindex 可阻止网址被编入索引

## 19. Core Web Vitals

**URL:** https://developers.google.com/search/docs/appearance/core-web-vitals?hl=zh-cn

**核心描述:**
核心 Web 指标是一组衡量网页加载性能、互动性和视觉稳定性的实际体验指标。

**三个核心指标:**
- **LCP（最大内容绘制）**：加载性能，衡量加载时间
- **INP（与下一次绘制的交互）/ FID（首次输入延迟）**：互动性，衡量响应速度
- **CLS（累计布局偏移）**：视觉稳定性，衡量页面布局的稳定性

**关键要点:**
- 强烈建议实现良好的 Core Web Vitals 以借助 Google 搜索取得理想成效
- 良好的 Core Web Vitals 得分并不能保证排名靠前
- 使用 Search Console 的 Core Web Vitals 报告监控
- 可使用 PageSpeed Insights、Lighthouse 等工具优化

## 20. 避免干扰性插页式广告和对话框

**URL:** https://developers.google.com/search/docs/appearance/avoid-intrusive-interstitials?hl=zh-cn

**核心描述:**
干扰性插页式广告和对话框会妨碍用户查看内容，给用户造成困扰并降低信任度，还可能导致搜索效果不佳。

**关键要点:**
- 干扰性对话框和插页式广告会导致 Google 难以理解内容
- 弃用全页插页式广告，改用占据一小部分屏幕的横幅广告
- 可使用 CMS 插件（如 WordPress 的简报注册插件）

**最佳实践:**
- 确保用户和搜索引擎能立即定位到所需内容
- 对应用安装横幅：使用 Safari 智能应用横幅或 Chrome 应用内安装体验
- 除非法律强制要求（如年龄验证），否则避免干扰性设计

**强制性插页式广告:**
- 如赌场网站年龄限制，允许 Googlebot 在不触发限制的情况下抓取内容

## 21. Signed Exchange (SXG)

**URL:** https://developers.google.com/search/docs/appearance/signed-exchange?hl=zh-cn

**核心描述:**
Signed Exchange (SXG) 让 Google 搜索能够以注重隐私保护的方式预提取内容，从而改善 LCP 和网页体验。

**关键要点:**
- SXG 让 Google 搜索预提取 HTML、JavaScript、CSS、图片、字体等关键资源
- 用户点击结果时网页更快开始渲染，LCP 得分可能降低
- 同时适用于 AMP 和非 AMP 页面

**实现和调试:**
- 遵循 web.dev 上的 SXG 实现指南
- 设置适当的失效日期（早于内容更新日期或签名 expires 值的较早者）
- 使用 SXG Validator Chrome 扩展程序调试
- Google SXG 缓存：子网域格式为 `xxx.webpkgcache.com`
- 使用 Search Console 的 AMP 状态报告监控 SXG 错误

## 22. 排名系统指南

**URL:** https://developers.google.com/search/docs/appearance/ranking-systems-guide?hl=zh-cn

**核心描述:**
Google 使用多种自动化排名系统搜索数千亿网页，考虑众多因素和信号，以显示最相关和实用的结果。

**排名系统列表:**
- **BERT**：理解字词不同组合的含义和意图
- **灾难信息系统**：在个人危机、自然灾害等情况提供及时信息
- **重复信息删除系统**：仅显示最相关结果，避免重复
- **完全匹配网域系统**：不将完全匹配查询的网域看得过于重要
- **更新系统**：针对时效性查询显示较新的内容
- **链接分析系统和 PageRank**：了解网页链接方式，判断网页内容
- **本地新闻系统**：识别和展示相关当地新闻媒体
- **MUM（多任务统一模型）**：理解和生成语言的 AI 系统，目前用于特定用途而非一般排名
- **神经匹配**：理解查询和网页中概念的表示形式并进行匹配
- **原创内容系统**：在搜索结果中突出展示原创内容
- **基于移除的降位系统**：处理大量移除要求的网站作为衡量因素
- **段落排名系统**：识别网页各个段落，更好了解与搜索内容的相关程度
- **RankBrain**：了解字词与概念之间的关系
- **可靠信息系统**：呈现权威网页、降低劣质内容排名、提升优质新闻排名
- **评价系统**：奖励包含深刻分析和原创研究的优质评价
- **网站多元化系统**：一般不在排名靠前结果中显示同一网站的两个以上网页
- **网络垃圾检测系统（SpamBrain）**：处理违反网络垃圾政策的内容

**关键要点:**
- 排名系统在网页级运行，也使用网站级信号和分类器
- 良好的网站级信号不保证所有内容都获得高排名
- 定期通过测试和评估改进排名系统，重大更新会通知

网络故事是热门"故事"格式的网络版本，将视频、音频、图片、动画和文字融合为动态消费体验。

- 避免：像素化图片、拉伸素材、不完整内容（要求点击跳转到其他网站）

### 32.3 网络故事内容政策

**URL:** https://developers.google.com/search/docs/appearance/web-stories-content-policy?hl=zh-cn

**关键要点:**
- 必须遵守 Google 探索政策、Google 搜索要素和总体政策
- 不允许侵犯他人版权
- 不允许文字过多（大多数页超过 180 字符）
- 不允许像素化或拉伸的图片/视频
- 不允许没有一脉相承主题或叙事结构
- 不允许内容不完整或要求跳转到其他网站获取信息
- 不允许以宣传服务/产品为唯一目标（允许联属营销链接，限小部分）

**URL:** https://developers.google.com/search/docs/appearance/structured-data/article?hl=zh-cn

**核心描述:**
添加文章结构化数据可使新闻、博文等内容以富媒体搜索结果形式显示（大图、标题等），提升可见性。

**适用类型:** Article, NewsArticle（新闻文章）, BlogPosting（博客文章）

**必需属性:**
- `headline`：文章标题
- `image`：图片 URL（1x1、4x3、16x9 比例至少各一张）
- `datePublished`：发布日期
- `author`：作者信息

**代码示例（JSON-LD）:**
```json
{
  "@context": "https://schema.org",
  "@type": "NewsArticle",
  "headline": "Title of a News Article",
  "image": [
    "https://example.com/photos/1x1/photo.jpg",
    "https://example.com/photos/4x3/photo.jpg",
    "https://example.com/photos/16x9/photo.jpg"
  ],
  "datePublished": "2024-01-05T08:00:00+08:00",
  "dateModified": "2024-02-05T09:20:00+08:00",
  "author": {
    "@type": "Person",
    "name": "John Doe"
  }
}
```

**作者标记最佳实践:**
- 标记所有作者，可指定多位作者
- 使用 `author.name` 属性指定作者名字
- 为每位作者设置适当的 @type（Person 或 Organization）

**技术指南:**
- 使用 JSON-LD、Microdata 或 RDFa 格式
- 使用富媒体搜索结果测试验证

**URL:** https://developers.google.com/search/docs/appearance/structured-data/organization?hl=zh-cn

**关键原则:**
- 没有必需属性，建议添加尽可能多的适用属性
- 建议放在首页或"关于我们"页面，无需在每个网页添加
- 使用最具体的 schema.org 子类型（如电子商务用 OnlineStore，本地商家用 LocalBusiness）

### 推荐属性

| 属性 | 说明 |
|------|------|
| `name` | 组织名称 |
| `url` | 官方网站 URL |
| `logo` | 组织徽标 URL |
| `description` | 组织描述 |
| `sameAs` | 社交资料链接数组（Facebook, Twitter, LinkedIn 等） |
| `email` | 联系邮箱 |
| `telephone` | 联系电话（含国家/地区代码和区号） |
| `address` | PostalAddress（含 streetAddress, addressLocality, addressCountry, addressRegion, postalCode），支持多个地址 |
| `contactPoint` | 客户服务联系方式（contactType, email, telephone） |
| `vatID` | VAT 编号 |
| `iso6523Code` | ISO 6523 标识码（推荐替代邓白氏编码） |
| `foundingDate` | 创立日期（ISO 8601） |
| `hasMerchantReturnPolicy` | 商家退货政策 |
| `shippingDetails` | 配送详情 |

## 62. 订阅和付费内容（PaywalledContent）

**URL:** https://developers.google.com/search/docs/appearance/structured-data/paywalled-content?hl=zh-cn

**核心描述:**
付费内容标记帮助 Google 区分付费内容与伪装真实内容的做法（cloaking），避免违反网络垃圾政策。

**代码示例:**
```json
{
  "@context": "https://schema.org",
  "@type": "NewsArticle",
  "headline": "文章标题",
  "image": ["https://example.com/photo.jpg"],
  "datePublished": "2024-01-15T08:00:00+08:00",
  "isAccessibleForFree": false,
  "hasPart": {
    "@type": "WebPageElement",
    "isAccessibleForFree": false,
    "cssSelector": ".paywall"
  }
}
```

**关键要点:**
- `isAccessibleForFree`：`false` 表示付费
- `hasPart.cssSelector` 指定付费内容的 CSS 选择器

## 总结：结构化数据实施原则

所有结构化数据类型的共同原则：
- 使用 JSON-LD 格式（推荐）
- 使用富媒体搜索结果测试验证
- 遵循结构化数据常规指南
- 数据必须真实反映网页内容
- 使用 Search Console 监控效果
- 添加的结构化数据越多，可能获得的增强功能越多
- 使用最具体的 schema.org 子类型
