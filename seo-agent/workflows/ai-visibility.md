# ④ AI 可见性监测（ai-visibility）

**这条工作流是什么**：在真实 AI 平台（DeepSeek / 豆包 / ChatGPT 等）按问题集做重复采样，测量目标实体/品牌在 AI 答案中的提及率、位置、竞品对比与引用来源结构。

**分几步**：6 步（输入确认 → 采样准备 → 重复采样 → 数据整理 → 分析 → 交付）

**每步做什么**：见下文。采样协议底稿在 `.agents/skills/yao-geo-ai-visibility/SKILL.md`（移植版）。

**哪几步停下来等你**：采样前确认（问题集/平台/轮数/登录状态）、报告交付后 sign-off。**采样进行中不打断，但每轮结束汇报进度。**

> ⚠️ **易碎依赖声明**（必须在报告与对话中如实说明）：
> - 依赖用户已在 browser-agent 中登录对应平台（平台可能要求验证码/风控）
> - 平台 UI 变动会直接导致采样失败 → 失败**记录阻塞原因**，不伪造数据
> - 概率类指标是**重复采样估计值，不是真值**；仅代表"这些平台在当前时刻、当前问法下的表现"
> - 采样频率保持低频人工节奏，**不做高频自动化**（平台规则与账号安全）

## 输入

| 项 | 必需 | 说明 |
|----|------|------|
| 目标实体 | ✅ | 品牌/产品/人名 + 别名清单（`实体名\|别名A\|别名B`） |
| 实体类型 | ✅ | person / company / product |
| 问题集 | ✅ | 每行一个问题（建议 10-20 个）；没有 → 先走 `⑤ intent-research` 生成 |
| 平台与轮数 | ✅ | 平台（DeepSeek/豆包/ChatGPT/…）；每问题轮数（建议 ≥5） |
| 竞品清单 | 建议 | 同类型竞品（与目标实体同类型过滤），用于对比矩阵 |

## 步骤

### 1. 输入确认与采样准备

- 确认实体名/别名/类型；竞品为同类型
- 检查 browser-agent 登录态：`read browser-agent/AGENTS.md`；如需登录，先 `open` 让用户完成登录，`state-save` 保存
- 建立采样目录：`output/{YYYY-MM-DD}-{实体}-ai-visibility/`（raw / report 两个子目录）

### 2. 重复采样（委托 browser-agent）

对每个问题 × N 轮：

1. 打开平台（已在登录态）→ **新建对话**（fresh window，避免上下文污染）
2. 提交问题（中文自然问法）→ 等待完整回答
3. 记录（raw JSON/Markdown，每样本一条）：
   - `platform` / `question_id` / `round` / `answer_date`
   - 完整答案文本
   - **目标实体是否提及** / 提及位置（第几段/第几个推荐位）
   - 引用来源：标题、URL/域名（点击展开验证可达）
   - 竞品出现情况
4. 轮间延迟：人工节奏（建议每平台轮间 ≥1 分钟，问题间随机间隔），避免高频
5. 失败样本**保留**（`ok=false` + 原因），分母保持 N

**记录格式**（raw 样本示意）：

```json
{
  "platform": "deepseek",
  "question_id": "q01",
  "round": 1,
  "answer_date": "2026-10-09",
  "ok": true,
  "answer_text": "……",
  "target_mentioned": true,
  "target_position": 2,
  "citations": [{"title": "…", "url": "…", "domain": "…"}],
  "competitors_seen": ["竞品A", "竞品B"]
}
```

### 3. 数据整理

- 合并全部 raw 样本 → 结构化表（问题 × 轮次 × 提及/位置/来源）
- 统计口径（分母 = 有效样本数，失败单列）：
  - 提及率 = 提及样本 / 有效样本
  - Top1 / Top3 / Top5 概率（按推荐位次）
  - 平均排名（提及样本内）
  - 引用来源结构（域名分布、官方 vs 第三方）
  - 竞品对比（同问题集下的提及率对比）

### 4. 分析

- 目标实体 vs 竞品的差距点（哪些问题类型下缺失）
- 引用来源结构 → 信源建设建议（官方资产 vs 需要外部信源）
- 归因保持谨慎：采样只是观测，不做因果结论（"提及率低" ≠ "因为页面 X"，只列相关线索）
- 与 `③ page-blueprint` / `① audit` 的衔接：可引用性问题回指页面素材缺口

### 5. 交付

- 按 `templates/ai-visibility-report.md` 输出到 `output/{YYYY-MM-DD}-{实体}-ai-visibility.md`（raw 数据放同目录 `-raw/`）
- 报告必须包含：平台/日期/问法/轮数、口径说明、原始数据可审计声明、失败样本与阻塞原因
- **Sign-off**：交付后停下

---

## 分析边界（硬规则）

- **不伪造**：平台回答、引用来源、排名数字——没有采样就没有数字
- **不越界**：不对平台内部排序机制做断言；不宣传"AI 优化技巧"超出 `google-currency.md` §3 官方立场
- **不违规**：不绕登录/验证码/风控；不做高频自动化；遵守平台条款
- **可审计**：保留原始答案文本与来源 URL，结论与 raw 数据一一对应
- 概率指标措辞统一为："在 N 次采样中，X 次提及（估计值）"，不写成"AI 平台排名第 X"

## Hard Stop

- 用户未确认问题集/轮数/平台前不开始采样
- 平台登录失效/风控拦截 → 停下报告，不尝试绕过
- 报告交付后停下，不自动开启新一轮采样
