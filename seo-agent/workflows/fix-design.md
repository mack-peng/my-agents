# ② 修改设计（fix-design）

**这条工作流是什么**：把审查发现（或用户直接给的问题清单）转化成前端项目**文件级、可实施的修改设计文档**（变更组 C1..Cn），可直接交给 `use code-agent` 实施。

**分几步**：5 步（输入确认 → 变更项映射 → 代码定位 → 变更组设计 → 交付）

**每步做什么**：见下文。核心要求：**每条变更的目标文件必须经过实际代码检索确认**，禁止凭框架惯例臆断路径。

**哪几步停下来等你**：变更项确认（输入有歧义时）、修改设计交付后 sign-off。**本 agent 不改代码。**

---

## 输入

| 项 | 必需 | 说明 |
|----|------|------|
| 审查报告 | 建议 | `output/` 里的 audit 报告路径；没有则用用户直接给的问题清单 |
| 项目路径 | ✅ | 本地项目绝对路径（用于定位文件与验证路径） |
| 实施范围 | 建议 | 只做 P0 / 做 P0+P1 / 指定条目 |

**与 ① 的衔接**：audit 报告 sign-off 后自然进入本流程；用户跳过审计直接给问题清单时，先快速核对问题清单的有效性（对照 `google-currency.md`，废弃项剔除或降级说明）。

## 步骤

### 1. 输入确认与变更项清单

- 从审查报告提取待修复项，逐条确认：问题成立（对照 currency）→ 范围（P0/P1/P2）→ 是否本轮实施
- 列出「变更项 → 对应审查条目」映射表，一次歧义问询（最多 2 问）

### 2. 变更项 → 代码位置映射

对每个变更项，实际读目标项目定位：

1. 读 `package.json` + 构建配置 → 确认栈
2. 用 `codegraph_explore`（项目有 `.codegraph/` 时）或文件检索，定位：
   - head 管理入口（layout / head 组件 / 模板）
   - 路由注册与路由表
   - sitemap / robots 生成逻辑
   - JSON-LD 组件或注入点
   - 图片组件 / 懒加载逻辑
   - i18n 配置
3. 记录精确路径（含行号范围），标注"确认路径"或"待确认"（待确认项在设计中显式说明）

### 3. 变更组设计（C1..Cn）

每个变更组按固定结构（见 `templates/fix-design.md`）：

| 字段 | 要求 |
|------|------|
| 问题来源 | 引用审查条目编号（A5/B3/…）或用户原始问题 |
| 目标文件 | 精确路径 + 关键行号范围（实际检索确认） |
| 修改方式 | 机制说明 + 示意片段（≤30 行伪代码，**不写完整实现**）；说明数据来源 |
| 依赖关系 | 与其它变更组的前后顺序（如 C2 依赖 C1 的 head 管理层） |
| 验证方法 | 可复测命令（`curl`/grep/富结果测试/本地构建）或检查点 |
| 风险与兼容性 | 影响的公共组件 / 多语言 / 缓存 / 构建产物 |

**分组原则**：
- 按依赖拓扑排序（head 管理层先行 → 逐模板接入 → sitemap/robots 生成 → schema → 图片/性能）
- 每组尽量独立可验证、可单独合并
- 成本标尺：S（0.5-1 人日）/ M（2-4）/ L（5-10），标注每组估算

### 4. 实施顺序与交接口

- 输出变更组依赖图（哪些可并行、哪些必须串行）
- 交接口说明：本文档可直接作为 code-agent 的输入（引用 Spec/设计格式：变更组编号 + 目标文件 + 验证方法）
- 如项目在 develop-agent 流水线中：建议作为 Phase 2 的输入材料

### 5. 交付

- 按 `templates/fix-design.md` 输出到 `output/{YYYY-MM-DD}-{项目名}-seo-fix-design.md`
- **Sign-off**：交付后停下，等用户确认；确认后提示"可 `use code-agent` 按变更组实施"
- 用户确认设计后如需修改 → 回到步骤 3 对应变更组

---

## Hard Stop

- **不修改目标项目任何文件、不提交代码**（交付边界：只出设计）
- 目标文件路径未经代码检索确认的，标记「待确认」，不得写成确定路径
- 审查报告未确认前不开始（除非用户明确跳过）
- 每次交付后停下，不自动开始实施

## 输出约定

- 变更组编号稳定（C1、C2…），审查报告条目与本设计双向可引用
- 示意片段总计每变更组 ≤30 行；不提供可直接运行的完整代码
- 每变更组必含验证方法——无法验证的设计不交付
