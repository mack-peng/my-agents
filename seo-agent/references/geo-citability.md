## 0. 立场声明（先读，防止跑偏）

1. **GEO = SEO 的同一套底座**（Google 官方）：AI 功能的资格底线是"已索引 + 有摘要资格"。先把 A-H 技术项做对，再谈可引用性优化。
2. **官方辟谣五件套**：llms.txt / chunking / AI 专用改写 / 不真实提及 / 为 AI 过度投资结构化数据——**都不需要**。
3. **但第三方研究指出了相关性信号**（非 Google 官方信号，引用需标注）：内容新鲜度、品牌提及、结构可抽取性等与 AI 引用有统计相关性。这些作为**优化机会**呈现，不作为"Google 排名因素"承诺。
4. **无平台采样数据时，不判断 AI 平台召回/排名/引用份额**——只诊断"公开答案素材是否完整、可抽取"。

## 1. 五阶段链路（诊断框架）

页面进入 AI 答案要穿过五关，任何一关断裂，前面的优化都白做：

```
发现 (Discovery) → 检索候选 (Retrieval candidate) → 正文抽取 (Main-content extraction) → 证据质量 (Evidence quality) → 生成引用 (Generated citation)
```

| 阶段 | 检查什么 | 常见断裂点 |
|------|---------|-----------|
| 发现 | robots、sitemap、内链可达、AI 爬虫访问 | OAI-SearchBot 被屏蔽；页面孤立无内链 |
| 检索候选 | 索引状态、query fan-out 覆盖（页面能回答相关问题族） | 页面只答一个窄问题，fan-out 子问题无素材 |
| 正文抽取 | 初始 HTML 可读、语义标签、模块可独立抽取 | CSR-only、主内容与导航混杂、视觉卡片无语义 |
| 证据质量 | 实体全称、数据、来源、日期、作者、边界 | 匿名、无日期、无来源、营销口号 |
| 生成引用 | 自包含答案块、键值对、对比表、原子事实 | 结论埋深处、答案依赖上下文、无独特数据 |

## 2. 五维评估（含权重，评估用，非 Google 信号）

### 2.1 可引用性 Citability（25%）

**强信号**：
- 章节前 40-60 词给出直接答案；结论前置
- 自包含答案块（脱离上下文可独立理解）
- 定义遵循 "X 是……" / "X 指……" 模式
- 断言带具体来源；独有数据点
- 关键信息出现在页面前 30%（第三方研究：约 44% AI 引用来自页面前 30%）

**弱信号**：泛泛陈述、无证据观点、结论埋深、无具体数据。

### 2.2 结构可读性 Structural（20%）

- 干净的 H1→H2→H3 层级；**问题式标题**（匹配查询模式）
- 短段落（2-4 句）；对比数据用表格；步骤/清单用列表
- 明确 Q&A 格式（可见问答）
- 弱信号：文字墙、层级混乱、信息埋在段落里

### 2.3 多模态（15%）

- 文本 + 相关图片；视频（内嵌或链接）；信息图/图表；交互工具
- 结构化数据支撑媒体（ImageObject/VideoObject）
- 注：多模态与 AI 答案选择的相关性为第三方论断，无官方数字

### 2.4 权威与品牌信号（20%）

- 作者署名 + 资历；发布/更新日期
- 引用一手来源（研究、官方文档、数据）
- 组织资质与从属关系；专家引语（带署名）
- 实体存在：Wikipedia/Wikidata、Reddit、YouTube、LinkedIn
- 新鲜度（第三方研究：<3 个月的页面被引用概率显著更高；6+ 个月未更新丧失引用资格）→ **定期刷新是最具杠杆的 GEO 动作之一**
- 弱信号：匿名、无日期、无来源、无跨平台品牌存在

### 2.5 技术可访问性（20%）

- 服务端渲染 vs 纯客户端内容（GPTBot/PerplexityBot 等多数 AI 爬虫**不执行 JS**）
- AI 爬虫 robots.txt 访问（见 `google-currency.md` §4）
- llms.txt：仅报告存在性，**不计权重**
- RSL 1.0 许可条款（完整性报告项）

## 3. 原子事实与可抽取模块

对页面核心事实做"原子化"检查（yao 方法移植）：

- **键值对**：规格、价格、服务范围（`<dl>`/表格承载）
- **原子事实**：主体 + 属性 + 数值 + 时间 + 来源 + 适用边界（一句一事实）
- **对比表**：同口径维度、表前声明口径
- **步骤**：前置条件、有序步骤、预期结果、错误码
- **问答**：真实问题 + 直接答案（不隐藏）
- **上下文无关摘要**：页面顶部/结尾各一段可独立理解的摘要
- **实体关系**：品牌/产品/场景/竞品/案例之间的关系有 `@id` 映射
- **chunk 引用准备度**：每个模块能被独立摘出且不丢主语

每个页面至少建议一个"可抽取事实模块"（事实卡 / 对比表 / FAQ / 步骤表 / 来源台账）。

## 4. 权威证据分层（报告中每个关键判断必须标记）

| 标记 | 含义 |
|------|------|
| **观察** | 来自页面 HTML/DOM、HTTP、schema、截图或可复测命令 |
| **官方** | 来自品牌官方页面/文档/帮助中心 |
| **标准** | 来自 Google Search Central、Schema.org、W3C、Web Vitals |
| **研究** | 来自论文或公开 benchmark（带出处） |
| **推断** | 基于证据推导，需日志/CMS/平台采样验证 |
| **缺口** | 无法前台判断或用户未提供 |

**禁止**：用 schema 声明正文没有的事实；用第三方文章替代官方价格/功能/边界；把"浏览器可见"等同于"初始 HTML 可读"；把"Google 可渲染"等同于"所有抓取器可渲染"。

## 5. 国内 AI 平台适配（yao 方法移植）

素材准备层面的差异（不是平台排名规则）：

| 平台 | 问法特征 | 页面素材对策 |
|------|---------|-------------|
| DeepSeek | 复杂决策、约束条件、风险权衡 | 增加条件对比、约束说明、风险/边界段落 |
| 豆包 / 元宝 | 日常生活化、业务场景口语 | 场景化问答、口语化 FAQ |
| Kimi / 千问 | 多轮追问、资料整合 | 保留追问链路可回放；文档式结构、引用齐全 |

常见中文问法：哪家好 / 怎么选 / 推荐 / 靠谱吗 / 多少钱 / 和某某比怎么样 / 适合谁。**竞品表述必须中性**，不制造无法证实的负面结论。
