# 首轮专业搜索迭代升级 Spec

## Problem

| # | 问题 | 影响面 |
|---|------|--------|
| 1 | `兴趣分析→推荐专业` LLM 输出 2-3 个专业名拼接（如 `计算机科学与技术 软件工程 人工智能`），知识库用整串多词混合查询，返回空 | 首轮分析报告缺失专业维度知识库数据 |
| 2 | 知识库无匹配时，下游 LLM 无数据支撑凭空推测专业-学校关系 | 兴趣匹配推荐准确性下降 |

## Related Spec

- 追问多校搜索迭代升级.spec.md（同模式根因，不同分支）

## Solution

### 现行链路

```
兴趣分析→推荐专业 (LLM)
  → 专业名称匹配搜索 (KB, 多词混合)
    → 合并搜索结果 (VA)
      → 精简去重 → 智能分析推荐 (LLM)
```

### 新链路

```
兴趣分析→推荐专业 (LLM, prompt 不变)
  → 拆解专业列表 (Code, NEW)
    → 迭代专业搜索 (Iteration, NEW, 并行)
        ├─ 专业名称匹配搜索 (KB, 移入迭代，逐专业查询)
        └─ → 合并专业搜索结果 (Code, NEW)
          → 合并搜索结果 (VA, 引用改为新输出)
            → 精简去重 → 智能分析推荐 (LLM)
```

### Part 1 — 保持不变

| # | Requirement | Description |
|---|-------------|-------------|
| 1 | `兴趣分析→推荐专业` prompt 不变 | 原输出「仅专业名，空格分隔」已满足下游拆分需求 |

### Part 2 — 拆解专业列表

| # | Requirement | Description |
|---|-------------|-------------|
| 2 | 新增节点，将 LLM 输出的多专业名空格分隔文本拆为单个专业名数组 | 输入：`计算机科学与技术 软件工程 人工智能`<br/>输出：`["计算机科学与技术", "软件工程", "人工智能"]`<br/>去重，上限 3 个。空输入返回空数组 |
| 3 | 空数组兜底 | 迭代 0 次执行，合并节点输出空数组，VA 仅含分数搜索结果 |

### Part 3 — 迭代专业搜索 + 合并结果

| # | Requirement | Description |
|---|-------------|-------------|
| 4 | 对数组中每个专业名单独搜索知识库 | 并行执行，每次迭代传入一个专业名，不与其它专业名混合 |
| 5 | 将原「专业名称匹配搜索」KB 节点移入迭代内部 | 每次只搜一个专业，命中率大幅提升 |
| 6 | 迭代结束后，合并所有命中结果 | 按 segment_id 去重，平铺为统一数组，格式与原 KB 输出一致 |
| 7 | `合并搜索结果` VA 引用改为合并后的输出 | VA 下游无感知 |

### Part 4 — 边界情况

| # | 场景 | 预期行为 |
|---|------|----------|
| 8 | 用户未填兴趣 → LLM 输出空 | 返回空数组，VA 仅含分数搜索结果 |
| 9 | 只有 1 个专业名 | 迭代 1 次，等效原行为 |
| 10 | 3 个专业，2 个命中 1 个未命中 | 命中专业数据合并传入下游 |
| 11 | 3 个专业全部未命中 | 返回空数组，分数搜索+网络搜索结果依然可用 |
