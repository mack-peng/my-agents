# ⑦ 能力接入（定位 → 能力矩阵 → spec → 实施）

进入条件：用户要「接平台能力 / 提升可玩性 / 分享性 / 社交性 / 接震动 / 分享 / 关注 / 排行榜 / AI / 安全区」。

本工作流只产出**设计与产物 spec**；代码实施走 `use code-agent`，打包回归走 ①，预览送审走 ⑥。

## Step 0 目标解析（通用入口；规则详见 AGENTS.md）

1. 用户点名小工具 / 项目路径 / appId → 直接用；
2. 未点名 → `ls output/*/` 读 `manifest.md` 列候选；
3. 无记录 → 一次集中问：小工具名称 + 项目路径 + 一句话定位。

禁止从会话上下文静默代入历史工具。

## Step 1 契约同步

1. 抓一次在线文档：<https://miniapp-sandbox.xiaohongshu.com/minitool/doc>，记录 `last-updated`；
2. 读 `references/online-capabilities-2026-11-10.md`（增量、版本门禁、与本地 skill 基线的冲突）；
3. 产出四类清单：
   - 本次可直接接入
   - 需版本门禁 / 能力检测
   - 内测 / 受限（需构建开关）
   - 不适用（写明原因）
4. 在线文档不可达时：用本地基线 + 增量文档保守实现，交付标注「未核验在线能力」。

## Step 2 产品定位 → 能力矩阵

先写清 5 行定位，再排优先级：

- 品类（技巧 / 解谜 / 经营 / 工具 / 生成器 / 社交）
- 核心循环与单局时长
- 分数 / 成就 / 内容驱动
- 分享素材（成绩图 / 作品图 / 通关图 / 无）
- 社交动机（排行 / 关注 / 评论 / 无）

再填矩阵，每个在线能力都必须在表中出现：

| 能力 | 优先级 | 最低版本 | 产品价值 | 入口 / 时机 | 失败降级 | 构建开关 |
| --- | --- | --- | --- | --- | --- | --- |
| … | P0/P1/P2/P3/不接 | … | … | … | … | … |

规则：

- **P0** 基础体验：安全区、震动；
- **P1** 分享性：分享成绩图、发笔记、评论、保存相册；
- **P2** 社交性：关注、排行榜；
- **P3** 增味：AI 点评、赞赏、陀螺仪；
- 内测能力默认 P2/P3 入口，版本 / 方法 / 运行不可用时隐藏；
- 核心玩法不得依赖任何内测能力；
- 不接的能力必须写原因，不允许沉默跳过；
- 全屏容器（小红书默认）：顶部 inset 必须覆盖状态栏 + 返回/更多浮层；优先用 `getWindowInfo.menuButtons` 的 `bottom`，缺失或调用失败时平台内 fallback 至少 104px；HUD 与主内容 `max-height` 同步调整。

## Step 3 产出能力 spec

路径：`output/{YYYY-MM-DD}-{slug}/{YYYY-MM-DD}-{slug}-capabilities.spec.md`

固定章节：

```md
# {小工具名} — 能力接入 spec

## Context & Assumptions
- 项目 / 版本 / 技术栈
- 产品定位（品类 / 单局时长 / 驱动 / 分享素材 / 社交动机）
- 在线契约版本（last-updated）
- 原则：核心玩法不依赖内测能力；全部能力检测；失败隐藏或降级
- 上传通道：Agent 上传 / 手动上传；AI 是否在构建内

## Capability Matrix
| 能力 | 优先级 | 最低客户端 | 产品价值 | 入口 | 失败 / 降级 | 构建开关 |

## UX Surfaces
### 开始页
### HUD / 游戏中
### 结算页
### 弹层 / 设置

## Share Card
尺寸、背景、文案、生成方式、用途、失败回退

## Copy Deck
分享标题 / 正文 / 评论 / 空榜 / AI 提示词 / 静态兜底 / 关注 / 赞赏

## Error & Fallback Matrix

## Build Flags & Upload Constraints

## Acceptance Criteria

## Sign-off
```

## Step 4 用户 sign-off

必须确认：

- 能力取舍与优先级
- 入口位置与文案
- 内测 / 受限能力的构建开关默认值
- 降级策略
- 分享图规格

未确认不进入实施。

## Step 5 交 `use code-agent` 实施

- 按 `code-agent/AGENTS.md` 的流程执行；本 agent 不改 `src/`；
- 交接内容：能力 spec 路径 + 项目路径 + 构建开关 + 验收标准；
- 代码完成后，要求 code-agent 给出变更文件清单与自测结果。

## Step 6 回归

1. 回 ① 重新打包：跑 audit，确认 §2.7 入口文件位置；
2. 若接入排行榜：⑥ 送审前勾选「用户头像昵称授权」；
3. 若接入 AI：确认上传通道（Agent / 手动）；
4. 全屏容器在模拟器 / 真机确认标题、得分、难度、开关不被状态栏与返回/更多遮挡；
5. 交付标注「模拟器 / Android / iOS 未实测」的部分。

## Hard Stop

- **只出设计，不改产品源码**；实施走 `use code-agent`。
- 内测能力（排行榜 / AI / 赞赏）不得作为核心玩法唯一路径。
- 所有平台调用必须：`window.xhs && miniTool && typeof fn === "function"` + 版本门禁。
- 不在游戏循环 / 高频定时器调用排行榜、AI、云存储；排行榜缓存 30–60 秒。
- 分享 / 关注 / 赞赏必须用户手势触发；分享仅全屏容器。
- 不采集 / 不落库用户昵称等平台资料；昵称只从 API 返回值直接渲染。
- 全屏容器不得假设 `safeArea.top` 只等于状态栏；必须把返回/更多 icon 的 `bottom` 纳入顶部 inset。
- 不伪造分享 / 提交 / 关注成功；以平台回执为准。
- 未确认发布配置时，不展示赞赏 / 关闭挽留；关闭挽留默认不启用。
- AI 内测能力默认不进入第三方 Agent 上传构建。
