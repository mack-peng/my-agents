# ③ 推广笔记（标题 / 正文 / Hashtags）

进入条件：用户要「推广文案 / 笔记 / 标题正文」。产出面向 XHS App 内的推广笔记消费视角。

## Step 0 目标解析（通用入口；规则详见 AGENTS.md）

1. 用户点名工具 → 用之；
2. 未点名 → `ls xhs-agent/output/*/` 列 manifest 候选让用户选；
3. 无记录 → 一次集中问：小工具名称 + 特性来源（项目路径 / 用户口述）+（可选）一条用户**真实战绩**。

数字约束先于动笔：所有战绩数字必须来自用户确认或项目常量，无来源即留占位符。禁止从会话上下文静默代入历史工具。

## 综合输入（目标解析后）

- 小工具名 + 版本 + 特性（从 workflow ①/⑥ 的产物记录或项目代码常量）
- 用户可选给一条**真实战绩**（如自己的通关秒数）；没给则删除数字语境

## 产出

按 `references/xhs-note-copy.md` 骨架产出：

- 标题 1 条（从 7 角度池选，≤20 字）
- 正文 A（完整版）或 B（短节奏版）二选一，问用户内容定调
- Hashtags 3-5 个（核心必带 #扫雷 #小游戏 #经典游戏）

## 配图（协作点）

- 需配图时**不挤在 xhs-agent 内产出**：提示「配图走 use image-agent」，把 app 视觉 / 成绩卡 / 上架封面作为
- 参考已产出的成绩卡视觉（来自 workflow ① 的 share 图）为优先选用

## 词汇安全

- 违禁：最强 / 第一 / 0 广告承诺 / 绝对通关
- 数字约束见 `references/xhs-note-copy.md`：必须来自当轮用户确认战绩或 `src/constants/sweep.js` 项目常量
- 数字没有来源时留 `{用户补充}` 占位并明说

## 交付

- 标题 / 正文 / Hashtags 三件套，直接复制即可发小红书；同时提示「发布时配生成好的封面/战绩图，点击率更好」，不主动追加做图
