# 视觉 QA 备忘（look 与数据画面实战教训）

画面侧经验，规则只在这里写一次。`look` 全绿只是底线——确定性/报错/裁切由机器抓，**口径、构图、观感仍要人眼看接触页**（`look` 输出的 contact sheet 必读；接触表还要**对照镜头表**逐拍过：每拍在吗、顺序对吗、starting state 帧一可读吗）。脚本/故事层的 QA（钩子、promise、节奏、cut list）见 `references/preproduction.md`「Story QA」。

## 手机可读性（1080×1920，2026-11 实测教训）

- **正文 ≥28px、辅助 ≥20px**（1080 宽）；12–16px 的图表标注在手机上等于不可读
- **一屏一个信息**：不要把 3 张数据卡塞满一屏；数字轮播比并排小卡好读
- **图表自绘**：柱/条/点阵/大字，比整页截图清楚；原文截图只做证据条（裁到关键 1–2 行）
- **左右 ≥84px、内容底 ≤1400**：贴边文字在圆角屏/播放器 UI 下会被裁
- **交付前缩到 390px 宽看一遍**（手机模拟），不是只看 1080 全尺寸

## 竖屏全片安全区（1080×1920，小红书全屏实测）

平台 UI 与字幕带是"隐形占用"，设计时就留空，事后不硬塞：

- **顶部 0–252 留空**：手机状态栏（~130-165px）+ 小红书顶栏。页眉/页号家具放 top: 252 起
- **字幕带 ~1465–1607**（系列基线 pos.y 0.80 / box 62%；Studio 新项目默认 0.72 → 带 ~1345–1420，先应用基线再设计）；页面内容不得压入
- **平台描述区 1620 以下留空**：小红书全屏播放时底部账号名/文案/进度条覆盖；永久性底注（出处行）不放这里
- **内容底边 ≤1400**：给字幕带留 60px+ 缓冲；面板/盖章/价格签全部在此线以上收口
- **瞬时元素（盖章等）放 1385–1455 带**，高度压到 ~70px（font 30 / padding 12 24）
- **持久底注没有安全位时的模式**：并入顶栏第二行右对齐（精简文字，与左侧 kicker 错开水平区间）
- **量了再改**：用 `node openfilm-agent/scripts/probe-safe-area.mjs output/<film-dir>` 量各页实际边界（依赖 openfilm fork 的 playwright-core），别心算布局

## 图表诚实（不编口径）

- 刻度、上限、单位是"事实"的一部分：**不得为了版面现编口径**。实测错例：把第三方智能指数条形图标注"满分区间 ≤60"——该指数没有固定满分，属于编造刻度
- 非满量程要写明（"图中上限 60 分" / "量程 0 – 1,200"），让观众知道条长被截
- 同一口径跨镜复用保持同尺度（43 / 55 / 58 都按 ÷60 缩放条长，观众才能跨镜对比）
- 图形与数值严格同构：bar 宽 = 值 ÷ 上限 × 轨宽；指针角 = 值 ÷ 量程 × 弧度；caption 写清数据来源

## 动效纯函数备忘

- 同一 t 永远同一画面：入场时刻全部写成显式常数表（从 VO cue + 0.35s 偏移推导，页内时刻 = VO cue + 场景提前量），不留"上一次的状态"
- SVG 指针/仪表映射公式先写注释再实现。实测坑：0 值应对应**左平（−90°）**，不是 −180°（会指地）；正确式：`ang = (v / 量程) × 180 − 90`
- 一个元素只吃一种动效（up / pop / stamp / wipe 二选一）——transform 会互相覆盖；复合动效用嵌套容器分担

## look 高发问题清单（修到全绿为止）

- **文案 typo 与现编口径**："上镜"（应为"上一镜"）、"满分区间"（应为"图中上限"）
- **首帧过空**：furniture（页眉/周带/出处栏）入场用负起点 `E(t, -0.06, 0.3)`，别留 0.3s 黑场
- **SVG viewBox 裁字**：弧两端刻度标签（如右端 1,200）越界——viewBox 留余量或把该标签 anchor 改 `end`
- **过渡期空洞**：数据元素进场前的大空档用 kicker/标题占位，避免成片"黑屏感"
- **溢出/被裁文本**：look 会报（clippedText / overflow），重点自查 chips 行、绝对定位的 stamp
- **组件样式误伤嵌套数字**：说明文字选择器写 `.fact span` 会命中数值里的嵌套 `<span>`（被当说明渲染成小字并强制换行）——组件 caption 一律用直接子选择器 `.fact > span`
- **出字早于旁白结束**：结尾大字/落版在最后一条字幕 cue 结束之后才 reveal（镜内时刻 ≥ VO 时长），否则与字幕同屏互压
- **接触表缩略图会误判**：300px 缩略里"卡片消失/文字脏"可能只是压缩所致（实测把三卡看成两卡）——可疑帧用 `openfilm look <t>` 出单帧全尺寸再判，别凭缩略图改代码

## 改口播后的画面返工

口播稿 v2 落定重录 VO 后：各镜内心时刻常数表全部按新 ASR cue 重算（页内时刻 = cue + 0.35），页面 `duration` 与 film.html `at` 链同步回填——只改音频不动页面时刻表，会出现"图不达意"（字说到数字，数字还没进来）。

## 共享家具与状态：两条纯函数硬规则（Nº06 实测）

- **家具只在页面加载时建一次**：页眉 / 周带 / 出处栏（furniture）在脚本顶层构建；`frame(t)` 只更新它们的位置与数值。把 `furniture()` 放进 `frame()` 会让每个被绘制的帧再 append 一套 DOM——同一 t 两次绘制画面不同，`look` 直接报 "same t drew two different pictures"
- **一切显隐/样式的变更必须是 t 的纯函数**：每帧都把 `display` / `visibility` / `cssText` / `innerHTML` 显式设回目标状态；`if (t > x) el.style.display = "block"` 这类单向变更是坑——帧会乱序绘制，先画晚帧再画早帧时残留状态会漏进早帧（实测：印章/徽标在 t<出现时刻被"提前"画出）
- 图片页必须 `ready: window.__brief.readyImages()`（等 `img.decode()` settle），否则 "media still seeking" 会造成双绘不一致

## 截图证据卡（shot-card）规范

- **页面实拍优先全宽**（= 内容宽，如 920/888）：把宽 1440 的页面塞进 500 宽卡片会横向切掉标题中段，看起来像排版事故（实测：TNW 卡 "GPT-6 Cyb…" 被横切）
- **竖向裁切终点必须落在干净边界**：标题区结束后的留白、hero 图边界、或 Credit 行之后、正文之前；切在段落行中间会露出半行字，观感被判"内容重叠"
- 卡宽变化时**同步换算 img 宽度**（如 1102→1058）保持同一裁切比例，不要只改卡宽
- **日期口径**：榜单/数据页截图日期可能与稿内数据日期不同（AA 截图 11/10、稿内引用 11/6 刷新）——卡面标注截图日期，正文仍按稿内口径；同页多档位（high/max）时自绘图形按"同家族取最高档"并标注，别让截图里的中间档和自绘条形打架
- 抓完必须**目检图片本体**（Read 截图）：空页/404/Cloudflare 拦截页体积异常小，肉眼一眼能排掉

## 窄列卡片布局（防重叠）

- 窄列（≤380px）卡片一律 **flex column**：标题 → 指标行（`nowrap`）→ chip **静态定位 + `margin-top:auto`**；绝对定位 chip 只有宽卡才安全
- 指标行「大数字 + 说明」估宽：中文 ≈ 字号 × 字数，西文 ≈ 0.55 × 字号 × 字符数。宽度不够时**降说明字号**（如 380 宽：56 数字 + 22 说明；284 宽：52 + 17），不要让它自己换行
- 多枚 chip / 需要"后出现"的元素：容器 `flex-wrap`，元素用 `visibility` 占位（hidden→visible），不要用 `display`（出现时推挤布局）
- 出现时机的状态切换照「纯函数硬规则」处理

## 素材获取 failsafe（截不到官方页时）

- OpenAI 官网、The Hacker News、Google/DDG/Bing 等会出 Cloudflare / 人机验证（"Verify you are human" / "Just a moment" / 选图验证）——**不绕过**，改用同主题的可靠报道页（TNW、MLQ、TechNode、benchlm、CyberSecurityNews 等）
- URL slug 别手拼：版本号/品牌常带连字符（`ling-3-2` vs `ling-32`），抓到前先用搜索结果核对；404 页截进卡是最尴尬的事故
- 截图固定流程：open → resize 1440×1000 → 需要时 `scrollTo` 到标题区 → screenshot → Read 目检 → 关闭会话

## 黑帧与「对不上」（2026-11 蜂蜜片复盘）

- 画面变黑就两种原因：一是 iframe 的 `#t=0,秒数` 被裁得比页面本身短（人在 Studio 裁过 24s，页面实际 27.1s，最后 3 秒全黑）；二是前一个镜头的结束时间和后一个镜头的开始时间没接上（S4 到 68.5 就没了，S5 却 68.7 才来，中间 0.2 秒黑）。人在 Studio 动过时间线后，把每个镜头的「终点 = 下一起点」对齐，再全片 look 一遍。
- 修 trim / 起点别手工猜，用 Studio 接口改，人的其他改动不会丢。先 `GET /api/projects/<id>` 拿到 `rev`，再 `POST /api/projects/<id>/edit`，body 写 `{base: rev, ops:[{op:'set', clip:'<镜头id>', field:'time', value:[0,27.1]}]}`（改起点用 `field:'at'`）。
- 查「画面和旁白对不对得上」：`GET /api/projects/<id>/captions` 拿到每句字幕的时间和内容，逐句看画面该出什么（差 0.3 秒内正常）。最容易犯的错是一行字塞两个数字、口播只说到前一个——把后一个数字拆出来单独设出现时间。
- 卡片/清单没讲到的部分，整块空着会被说「空白」，留 0.28 的幽灵行更糟。两个好用的做法：三张卡的标题先以半透明出现，内容等口播补；或者清单常亮 0.7，讲到哪条就给哪条打勾。另外画面底部一大片空是留给字幕和平台的，不是 bug。
- look 单帧里元素「不见了」，先别改代码，可能是 look 偶发。起个本地 http.server + openfilm 自带的 playwright-core 打开页面，直接调 `window.film.frame(t)` 看 DOM 里到底显不显示，确认了再动手。
