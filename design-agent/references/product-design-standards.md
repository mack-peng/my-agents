# 产品设计参考标准

整理自钉钉开放平台设计规范、Atlassian 产品设计方法论、人人都是产品经理界面设计规范。

---

## 一、产品设计流程（Atlassian）

产品设计是"发现问题 → 创造方案 → 交付价值"的完整闭环：

```
用户研究 → 定义问题 → 构思方案 → 原型 → 测试 → 发布 → 迭代
```

### 核心原则

| 原则 | 含义 |
|------|------|
| **Problem-first** | 先搞清楚"要解决什么"，不要直奔方案 |
| **跨职能协作** | 设计、工程、产品一起参与，不是设计丢墙 |
| **验证驱动** | 每个假设通过用户测试或数据验证 |
| **迭代思维** | 产品没有"做完"的那天 |
| **价值导向** | 功能是手段，用户价值是目的 |

---

## 二、设计规范必备要素（人人都是产品经理）

设计规范是团队的"通用语言"，必须定义清楚：

| 要素 | 内容 |
|------|------|
| **色彩系统** | 品牌色、辅助色、功能色（成功/警告/错误）、中性色阶 |
| **字体系统** | 字族、字号层级、字重、行高 |
| **间距系统** | 基准网格（4px/8px）、内外边距规则 |
| **组件库** | 按钮、输入框、卡片、弹窗的状态（默认/悬停/禁用/加载） |
| **图标系统** | 风格统一、尺寸标准、命名规范 |
| **动效** | 缓动曲线、持续时间、过渡场景 |
| **文案调性** | 语气、术语、标点规范 |

规范不是一次写完的，随产品演进持续维护。

---

## 三、企业级产品底线（钉钉开放平台）

| 维度 | 要求 |
|------|------|
| **一致性** | 遵循平台设计语言，控件和交互模式统一 |
| **稳定性** | 性能基线、异常处理、容灾机制必须明确 |
| **安全性** | 数据加密、权限管控、认证机制 |
| **可发现性** | 应用图标/截图/描述必须清晰传达价值主张 |
| **文档化** | API、鉴权、安全策略必须有文档可查 |

## 四、审查清单

### UI 设计

- [ ] 是否有设计规范文档
- [ ] 色彩系统是否完整（品牌色/功能色/中性色）
- [ ] 字体层级是否成体系（字号/字重/行高）
- [ ] 间距是否遵循网格系统
- [ ] 暗色模式是否有定义
- [ ] 响应式断点是否有明确规则

### 交互/UX

- [ ] 是否"问题优先"而不是"功能堆积"
- [ ] 用户核心路径是否有断点
- [ ] 每个操作是否有状态反馈（加载/成功/失败/空）
- [ ] 错误状态是否有引导（不是只有报错）
- [ ] 表单提交是否有防重复和校验反馈

### 转化/营销

- [ ] 价值主张是否在 3 秒内传达
- [ ] CTA 是否显眼且文案有行动导向
- [ ] 信任信号是否充足（案例/数据/客户Logo/团队）
- [ ] 联系/咨询路径是否最短

### 品牌形象

- [ ] 定位是否一以贯之（从 title 到 footer 是一个故事）
- [ ] 视觉调性是否匹配业务属性
- [ ] 团队/公司介绍是否存在
- [ ] 内容更新是否活跃（有无"死页"）

### SEO/性能

- [ ] 每个页面有独立 title/description
- [ ] 结构化数据（JSON-LD）是否完整
- [ ] 图片有 alt 且已优化
- [ ] Core Web Vitals 在合理范围
