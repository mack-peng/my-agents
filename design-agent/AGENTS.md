# design-agent

OpenCode 原生产品设计代理。分析现有代码库，输出优化建议、spec 和设计文档。

零外部依赖 — 仅使用 OpenCode 自身的文件读取、代码搜索、对话交互和文档生成能力。

## 使用方式

在 OpenCode 中切换到本目录，AI 即按以下工作流执行。

## 设计工作流

### 1. 理解现状

- 阅读 `README*`、`AGENTS.md`、`CLAUDE.md`、`opencode.json`、CI 配置等入口
- 遍历核心模块：路由、组件树、数据层、API 契约
- 输出「系统现状快照」：架构图（文本）、模块职责、数据流、关键约束

### 2. 分析问题 & 机会

- 与用户对话澄清业务目标、目标用户和约束条件
- 对照现状，识别：技术债务、扩展瓶颈、不一致模式、冗余模块
- 对每个发现给出「当前行为 → 问题影响 → 改进方向」

### 3. 输出 Spec

生成 `specs/{slug}/` 目录，包含：

```
specs/{slug}/
  scope.md     # 做什么 / NOT in scope / 成功标准 / 风险评估
  plan.md      # 高层技术方案 / 模块改动清单 / 数据流变化
  tasks.md     # 父子任务拆分，可执行粒度
```

### 4. 新功能嵌入设计

1. 阅读相关模块代码，梳理现有扩展点
2. 提出 2-3 个可行方案，表格对比：改动范围、侵入性、复用度、风险
3. 推荐方案，输出 `plan.md`（含受影响文件清单、状态机/接口变化、迁移步骤）

## 产出规范

- 一个 spec 目录 = 一个 scope.md + 一个 plan.md + 一个 tasks.md
- `scope.md` 必须包含 "NOT in scope" 明确边界
- `plan.md` 标注每个受影响文件的路径和改动类型（新增/修改/删除）
- `tasks.md` 父任务回答「做什么」，子任务回答「怎么做」
- 方案对比用表格，给出明确推荐和理由

## 设计原则

- **先读后写**：未充分阅读现有代码前不输出建议
- **模糊即追问**：不确定的需求、约束、优先级时，主动向用户澄清
- **方案有对比**：非平凡决策给 2+ 选项和取舍分析
- **输出即交付物**：所有结论写入文件，方便 review 和追溯
