# 构图与排版

目标：让图片在**信息、审美、品牌**三方面都成立，并且在平台缩略图尺寸下仍然可读。判断标准不是"看起来还行"，而是：**它只能属于这个主题，换成另一家公司就不成立。**

## 1. 画布与网格

- 画布尺寸精确到像素；`<meta name="viewport">`、`html/body`、`.still` 三者必须一致。
- 用 12 栏网格 + 8px 基线：
  - 页边距：宽度 6–8%（1440 用 88–116px；1280 用 80–102px；810 用 52–64px；900 用 56–72px）。
  - 栏间距：宽度的 1.5–2%。
- 所有关键内容放在安全区内；装饰层可以出血，但加 `data-bleed`，并在交付前确认没有被裁掉重要信息。
- 画布禁止滚动条：`html, body { overflow: hidden; }`。

## 2. 视觉重心与光学居中

- 几何居中不等于视觉居中。深色底、顶部品牌栏、底部元数据会把视觉重心拉低，主内容整体下移 2–4% 校准。
- 做法：主内容用 flex `justify-content: center`，再 `transform: translateY(calc(var(--h) * 0.02))` 微调；不要只靠 `flex-start`。
- 一张图只允许一个**主视觉锚点**：大标题、主体图像、或一个巨大的数字。其它元素围绕它建立层级。
- 主视觉锚点不要放在平台 UI 覆盖区（见 `platform-specs.md`）。

## 3. 层级

最多三层，超过三层就删：

1. **主层**：标题 / 主图 / 大数字。占视觉重量 60–70%。
2. **支撑层**：副标题、一句解释、数据卡、产品图。
3. **元信息层**：品牌名、期号、日期、标签、页脚。

层级必须通过**尺度、颜色、字重、留白**同时区分，不能只靠字号：

- 主标题与副标题字号比 ≥ 1.8。
- 主标题与正文比 ≥ 3。
- 强调色面积 ≤ 10%；同一张图只用一个强调色。
- 同层级元素对齐；不同层级之间留白 ≥ 一个行高。

## 4. 字体

默认两套字体，最多两套：

- 标题/正文：`PingFang SC`（`Hiragino Sans GB`、`Noto Sans CJK SC` 兜底）。
- 元数据/数据/英文标签：`Maple Mono NF CN`（缺失时 `SF Mono`、`Menlo`）。
- 需要强科技感时，标题可切 Maple Mono，但正文仍用 PingFang SC，避免全篇等宽造成阅读疲劳。

字号基线（以画布宽度为基准，用 `--u = 宽 / 100`）：

| 元素 | 1440 宽 | 1280 宽 | 810 宽 | 900 宽（公众号） |
|---|---|---|---|---|
| 主标题 | 96–180px | 84–150px | 60–96px | 48–72px |
| 副标题 | 36–52px | 32–44px | 28–36px | 22–28px |
| 正文 | 28–34px | 24–30px | 22–26px | 18–22px |
| 元数据 | 20–24px | 18–22px | 16–18px | 14–16px |
| 数据大字 | 72–150px | 64–120px | 48–80px | 40–64px |

排版规则：

- 大标题字距 `-0.02em` 到 `-0.06em`；行高 `1.0–1.12`。
- 正文行高 `1.4–1.6`；字距 `0.01em`。
- 中文标题尽量手动 `<br>` 控制断行；不要依赖浏览器自动换行。每行 6–12 个汉字为宜。
- 英文/数字用等宽字体时开启 `font-variant-numeric: tabular-nums`。
- 不使用伪粗体；不使用 3 种以上字重。
- 最小可读字号：在 1080 宽输出中，正文 ≥ 24px，元数据 ≥ 18px；公众号 900×383 中元数据 ≥ 14px。

## 5. 颜色

- 一套配色最多 4 个角色：背景、主文字、次要文字、强调色。
- 默认深色科技编辑感：
  - 背景 `#0B0C0E`
  - 主文字 `#F5F5F0`
  - 次要 `#8A8F98`
  - 强调 `#D7FF3F`
  - 分割线 `rgba(245, 245, 240, 0.14)`
- 对比度：正文 ≥ 4.5:1；大字号 ≥ 3:1。图片背景必须加暗遮罩/渐变，不能直接压字。
- 强调色只用于：一个关键词、一个数字、一条引导线、一个按钮/标签。不要整段文字都用强调色。
- 用渐变、噪点、网格、暗角增加深度；强度控制在"几乎注意不到"的程度。

## 6. 分层结构

从上到下：

1. **背景**：纯色 / 渐变 / 摄影图 / AI 图。
2. **氛围**：暗角、渐变遮罩、网格、噪点、光晕。
3. **主体**：人物 / 产品 / 插画 / 3D 物体。
4. **遮罩**：保证文字可读的 scrim（黑色渐变、局部模糊、色块）。
5. **文字**：eyebrow → 主标题 → 副标题 → 正文。
6. **品牌**：Logo、品牌名、期号。
7. **元数据**：日期、作者、标签、页脚、二维码。

实现约定：

- 每层一个独立元素，命名清晰（`.bg`、`.scrim`、`.hero`、`.title`、`.brand`、`.meta`）。
- 绝对定位用于主构图；flex/grid 用于文字块内部对齐。
- 不滥用 `z-index`；按 DOM 顺序叠放，必要时只给 1–3 个特殊层设 `z-index`。
- 可编辑性优先：文字是文本节点，不是图片；Logo 是原始 SVG/PNG，不是重绘。

## 7. 构图模式

按内容选一种，不要混合太多种：

- **左对齐编辑部**：左侧大标题 + 右侧/背景主图；适合周刊、深度内容、品牌观点。
- **居中海报**：标题居中，上下留白，底部元数据；适合金句、活动、发布。
- **分栏网格**：左文右图或上文下数据卡；适合信息密度高的封面。
- **满版图 + 底部渐变**：摄影/AI 图占满，文字压在下 1/3；适合人物、场景、产品。
- **数据卡堆叠**：2–3 个大数字 + 标签；适合报告、榜单、增长数据。
- **贴纸/拼贴**：纸张、胶带、手写标注；适合生活方式、教程、轻松内容。
- **UI 展示**：真实截图 + 透视/阴影/背景光；适合产品发布、功能更新。

每种模式都必须回答：**为什么这张图只能属于这个主题？** 如果换成另一家公司也成立，重做。

## 8. 图片处理

- 图片一律 `object-fit: cover`，用 `object-position` 控制焦点；不拉伸、不挤压。
- 主图分辨率 ≥ 展示尺寸的 1.2 倍；低于 1.0 倍会糊，必须换图或缩小展示。
- 摄影图加暗遮罩/渐变，保证文字对比；不要把文字压在杂乱区域。
- 产品截图必须用真实截图；需要简化时裁剪/放大，不重绘 UI。
- AI 图只做背景/插画/纹理；不让 AI 画中文、Logo、真实界面、数据图表。
- AI 图提示词里明确 "no text, no letters, no watermark, no logo, no UI"，并主动留出文字区。

## 9. 中文排版细节

- 中英文混排加空格：`AI 工作台`、`1440 × 1920`、`2026.10`。
- 数字与单位不拆行：`1440px`、`1280 × 1024`。
- 标点用中文全角；英文括号/冒号按语境统一。
- 避免孤字/孤行：标题最后一行至少 2 个汉字；必要时手动断行。
- 避免标题压住人脸、产品主体、二维码。
- 长标题优先缩短文案，不靠缩小字号硬塞。

## 10. 多尺寸适配

- 3:4 → 5:4 / 2.35:1 / 1:1 是**重排版**，不是缩放。
- 共享：色板、字体、Logo、图像素材、文案层级。
- 重排：主视觉位置、标题字号、数据卡列数、页边距、安全区。
- 每个尺寸单独一个 HTML（或同一 HTML 用 CSS 媒体查询切换布局），不要用一个固定画布 `transform: scale()`。
- 同一组多尺寸交付时，生成 contact sheet 对比，确保不是"一张图被拉成不同比例"。

## 11. 自检

- **眯眼测试**：眯眼还能看出主标题和主视觉吗？
- **缩略图测试**：缩到 320px 宽，标题仍可读、主体仍可辨吗？
- **灰度测试**：去色后层级还成立吗？如果只靠颜色区分，重做。
- **裁切测试**：按平台安全区裁掉边缘，关键信息还在吗？
- **替换测试**：把品牌名换成竞品，图还成立吗？成立说明不够贴题，重做。
- **事实测试**：每个数字都能指出来源吗？
